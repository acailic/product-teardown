# Teardown: Checkly — monitoring as code, metered by the check run

- **Date analyzed:** 2026-11-08
- **Category:** B2B · developer SaaS (synthetic monitoring + E2E testing)
- **Model:** tiered subscription + usage-based expansion; free tier; bootstrapped start → VC-backed
- **Prices as seen (2026-11-08):** Hobby $0 (10 monitors) · Starter $29/mo, $24 annual · Team $80/mo, $64 annual · Enterprise custom · modules sold separately: status pages $9–34/mo, AI RCA $12–49/mo (annual) ([pricing](https://www.checklyhq.com/pricing/), [pricing.md](https://www.checklyhq.com/pricing.md))
- **Revenue evidence:** funding **verified** ($10M Series A 2021, $20M Series B 2024 — [A](https://www.checklyhq.com/blog/checkly-raises-10m-for-developer-owned-operations/), [B](https://www.checklyhq.com/blog/announcing-20m-to-enable-engineers-to-detect-and-r/)); revenue itself **estimated** — never disclosed; "more than 1,000 companies" is a [vendor claim](https://www.checklyhq.com/blog/announcing-20m-to-enable-engineers-to-detect-and-r/)

## 0. The essence (ELI9)

Checkly rents out a robot customer. Every minute or so, that robot visits a company's website like a person would: it logs in, puts things in a basket, clicks "pay" with a fake card, and pokes the behind-the-scenes machinery (APIs). If anything gets stuck, it phones the engineering team before real customers notice. Companies pay a monthly rent for the robot, plus more the more often it runs — like paying per ride. Two people built the first version themselves; then big investors gave them millions to grow, and over a thousand companies now keep this robot on staff.

## 1. What it is, and for whom

Checkly is a synthetic monitoring and continuous testing platform: API checks, browser checks that run Playwright scripts on a schedule from 6–22 global regions, heartbeat monitoring for cron jobs, status pages, and OpenTelemetry traces with AI root-cause analysis ([llms.txt scope](https://www.checklyhq.com/llms.txt)). Its signature is **monitoring as code**: checks written in TypeScript, Terraform or Pulumi, versioned in Git, deployed from CI with `npx checkly deploy` — "no agents required." Founded 2018 in Berlin by Hannes Lenke (CEO) and Tim Nolet, now remote with offices in Berlin and New York ([about](https://www.checklyhq.com/about/)). The primary user is the DevOps/SRE/platform engineer who owns reliability of user-facing services. In 2026 the company leans into AI-agent distribution: an [llms.txt](https://www.checklyhq.com/llms.txt) site index, an MCP server, installable "agent skills" ([about](https://www.checklyhq.com/about/), "Application Reliability For Agents").

## 2. How it earns

**Subscription tiers whose revenue unit is the check run** — a single API or browser (Playwright) execution — plus monitors and two separately sold modules ([pricing, seen 2026-11-08](https://www.checklyhq.com/pricing.md)):

- Hobby $0 (hard-capped 10 monitors, 10k API + 1k browser runs).
- Starter $29/mo monthly, $24 annual — 50 monitors, 25k API + 3k browser runs, 3 users.
- Team $80/mo monthly, $64 annual — 75 monitors, 100k API + 12k browser runs, 10 users, 22 regions, private locations.
- Enterprise custom.

Usage expands the bill: +25 monitors $8–10/mo, browser runs $4–5 per 1k, API runs $1.80–2 per 10k, plus automatic overages ($6.25–6.50/1k browser). The vendor claims monitoring-as-code customers "tend to run 10x more checks" ([Series A](https://www.checklyhq.com/blog/checkly-raises-10m-for-developer-owned-operations/)) — the code workflow is also the meter expander. **Revenue: estimated**, never disclosed. Verified milestones: bootstrapped start → seed March 2020 → [$10M Series A led by CRV](https://www.checklyhq.com/blog/checkly-raises-10m-for-developer-owned-operations/) (2021) → [$20M Series B led by Balderton](https://www.checklyhq.com/blog/announcing-20m-to-enable-engineers-to-detect-and-r/) (2024; over $30M announced across rounds). Scale vendor claims: 1 billion cumulative check runs (2021), "more than 1,000 companies… millions of checks per day" (2024); 24 people joined in 2025 from 12,479 applications ([hiring post](https://www.checklyhq.com/blog/checkly-2025-hiring-data/)) — a scale-up, not a micro-SaaS.

## 3. Who the customers are

- **Developer-platform teams at product companies** — the paying core. Named vendor-claim customers from the [Series A post](https://www.checklyhq.com/blog/checkly-raises-10m-for-developer-owned-operations/): Vercel (checks on every deploy), 1Password (auto-created API monitors), "the largest retailer in Europe" (all config in the Terraform provider).
- **SRE/DevOps leads at mid-to-large firms** — [customers-page testimonials](https://www.checklyhq.com/customers/) (vendor-published): DVAG (German financial services), Chronosphere; "we now know as soon as some of our endpoints misbehave".
- **Individual developers** — free Hobby tier, "thousands" joined after the free plan launched in 2021 (vendor claim); open-source tooling ([checkly-cli](https://github.com/checkly/checkly-cli) ★97, [terraform-provider-checkly](https://github.com/checkly/terraform-provider-checkly) ★45) as distribution.
- **Enterprises** — custom pricing; 2025 hired three enterprise account executives from one posting ([hiring post](https://www.checklyhq.com/blog/checkly-2025-hiring-data/)).

## 4. Why they use it

The job: **prove that critical user journeys work right now, from outside, before customers notice** — reusing the Playwright skills engineers already have instead of a proprietary recorder. Monitoring-as-code fits the Git workflow: check changes get reviewed, versioned and deployed like app code. The realistic alternatives define the competition: legacy uptime checkers like Pingdom (URL pings, no code, no Playwright), synthetics inside observability suites (Datadog et al. — Checkly runs ["alternative to" pages](https://www.checklyhq.com/alternatives/datadog/) against them), self-hosted OSS, or CI-only tests that don't watch production. The founder keeps expectations honest: "API monitoring is a very crowded space" ([Tim Nolet, HN](https://news.ycombinator.com/item?id=33468052)).

## 5. What I would build better

1. **Workflow-level regression, not endpoint-level.** Checkly deliberately scopes itself to API and browser journeys ("It is not an APM… it observes an application the way a customer does" — [llms.txt](https://www.checklyhq.com/llms.txt)). Business workflow *configurations* — n8n automations, Jira workflows, Salesforce flows — sit in a gap everyone skips: changed JSON silently breaks business rules and is "tested" by eyeballing. Budget in that adjacent layer is proven today: [ScriptRunner for Jira ≥33,927 installs](https://marketplace.atlassian.com/apps/6820/scriptrunner-for-jira) and [JMWE ≥16,190 installs](https://marketplace.atlassian.com/apps/292/jira-misc-workflow-extensions-jmwe) (Atlassian Marketplace, seen 2026-11-08). A "semantic diff + replay before deploy" offer on Checkly's own revenue unit — the run — is the open flank.
2. **A flat-fee tier for the non-platform buyer.** The pricing suits teams that love meters: prepaid blocks, overage tables, a grandfathering FAQ about price jumps ([pricing.md](https://www.checklyhq.com/pricing.md)). Ops teams that run monthly CSV imports into an ERP will never sign up for per-run billing; a flat "per workflow suite" tier would convert the segment meters scare off.
3. **Unbundle AI triage from invocation caps.** Resolve meters root-cause analysis at 10/50/150 invocations per month even at $39–49 ([pricing.md](https://www.checklyhq.com/pricing.md)) — when a bad night produces dozens of failed checks, the diagnostic tool hits its cap. Bundling RCA into the Detect run price would make Resolve the reason to upgrade, not the friction.
